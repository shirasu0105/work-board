## ワイヤーフレームの位置づけ

**ラフ案・参考デザイン**です。最終UIではなく、**情報密度・画面構成・操作導線**を確認するためのもの。
本実装では、技術スタック（Next.js / TypeScript / Tailwind CSS / SQLite）に沿って正規のコンポーネントを使ってください。

## 採用したレイアウト方針

- **サイドナビ + シングルカラム + カード中心**
- タスク一覧は **かんばん** を主案、**リスト** を副案（切替UI）
- Inbox のクイック追加は **上部の常設バー方式** を採用（要件書 §10.2 の「素早く記録」を最重視）
- メモ作成の種別切替は **上部タブ方式** を採用
- モバイルは **ボトムタブ + 中央クイック追加ボタン**

> ワイヤーフレーム本体（`仕事効率化アプリ ワイヤーフレーム.html`）には、未採用パターン（Inbox クイック追加 4案、メモ種別切替 3案、タスクリスト副案）も並んでいます。判断材料として参照可能です。

## メモ種別フォーマットの実装メモ（重要）

要件書 §10.9 に対応。**種別を選ぶと入力フィールドが入れ替わる** のがポイント。

| 種別 | 必須 | フィールド構成 |
|---|---|---|
| 議事録 | 会議名(=タイトル), カテゴリ | 日時 / 参加者 / 目的 / 議題 / 決定事項 / 宿題 / 自分のNext Action |
| TTメモ | タイトル, カテゴリ | 誰から / 背景 / 教えてもらった内容 / **ファクト → 抽象化 → 転用** |
| 思いつきメモ | タイトル, カテゴリ | 内容 / **ファクト → 抽象化 → 転用** / タスク化候補 / Someday候補 |
| 調査メモ | タイトル, カテゴリ | 調査テーマ / 調査内容 / 分かったこと / 結論 / 次に確認すること |
| 作業ログ | タイトル, カテゴリ | 作業内容 / 結果 / 詰まった点 / 対応内容 / 次にやること |

共通の自動管理: ID / 作成日時 / 更新日時。
共通の任意入力: 関連プロジェクト。

## ステータスとカテゴリ（共通スキーマ）

タスクのステータス（要件書 §10.5.4）:
```
未着手 | 対応中 | 待ち | 保留 | 完了
```

「待ち」は単なるステータスではなく、§10.6 の **待ち相手 / 待ち理由 / 確認予定日 / 待ち日数** を伴うサブ状態。
ステータス変更時に「待ち相手」「待ち理由」を必須で求める導線にしてください。

カテゴリは要件書 §10.3 に従い `カテゴリ名(必須) / 説明(任意) / 表示順 / 有効状態` を持つ。
すべてのタスク・プロジェクト・メモは必ずカテゴリに所属する。

## 推奨実装順（MVP）

1. **データモデル + マイグレーション**（SQLite, Prisma 推奨）
2. **カテゴリ管理**（他すべての前提）
3. **タスク CRUD + ステータス**（かんばんは後でOK、まずリスト）
4. **Inbox**（追加 → 振り分け）
5. **プロジェクト CRUD + タスク紐付け**
6. **待ち状態管理**（タスク機能の拡張として）
7. **メモ管理 + 種別フォーマット**
8. **ホーム**（既存データを集約表示）
9. **日次ジャーナル**（未完タスクからの選択 → 翌日表示）
10. **週次レビュー**（簡易実装）
11. **タスクかんばん表示**
12. **検索・絞り込み**（メモ/タスクとも簡易実装）

## デザイントークン（ワイヤーフレーム時点・参考値）

```css
--ink: #1a1a1a;        /* 主要テキスト */
--ink-2: #4a4a4a;      /* 副テキスト */
--ink-3: #8a8a8a;      /* 補助テキスト */
--ink-4: #c8c4be;      /* 罫線 */
--paper: #fbfaf6;      /* 背景 */
--paper-2: #f3f0e8;    /* 副背景・ヘッダ */
--accent: #d96642;     /* coral アクセント */
--accent-soft: #fde6dd;
--hl: #fef0a8;         /* ハイライト */
```

Tailwind 化時は `theme.extend.colors` で `ink / paper / accent` を定義することを推奨。
ただし、ワイヤーフレームの手書き風スタイル（`filter: url(#sketchy)`、Yomogi フォント等）は実装版には持ち込まない想定です。

## PDF の生成方法（再生成したい時）

このパッケージの `wireframes-print.pdf` を作り直したい場合:

1. `reference/wireframes-print.html` をブラウザで開く
2. Cmd+P (Mac) / Ctrl+P (Windows) で印刷ダイアログ
3. 「PDFに保存」、用紙サイズはカスタム（推奨: 1500 × 1000px）、余白なし、背景グラフィック有効
4. `reference/wireframes-print.pdf` として保存

## 対象外（要件書 §11.3）

以下は MVP では実装しないので、ワイヤーフレームにも含めていません。

- 詳細なレビュー履歴 / タグ / 添付ファイル / 通知 / AI連携
- 認証・認可 / 複数ユーザー対応 / クラウド同期
- タスク依存関係 / 繰り返しタスク / 優先度管理 / 作業時間管理

## 連絡事項

- ワイヤーフレームと要件書で齟齬がある場合、**要件書を正とする**
- ワイヤーフレームに含まれる仮データ（タスク名等）は実装時に削除し、空状態UIを別途設計する
- 空状態UI / エラー状態 / バリデーション表示はワイヤーフレーム未着手。実装時に追加してください
