# 使い方ガイド — python-manager

製造業向け画像 AI 開発支援用の Python スクリプトをローカル WebUI で一元管理するアプリ。誰でもこのドキュメントだけを読めば、本リポジトリからアプリを起動して使えるようになることを目指す。

---

## 1. このアプリでできること

日常業務で使う Python スクリプト（画像加工、データセット生成、CSV 出力、AI 学習スクリプトなど）を、コマンドライン引数を覚えずに **WebUI から一覧→設定→実行→結果確認** できる。

主な解決する困りごと：

- 実行時のパラメータ入力が煩雑
- パスや設定値をスクリプト内にベタ書きしてしまう
- 過去に作ったスクリプトを見失う
- チーム共有時の使い方説明が大変
- 実行結果の確認がしにくい

---

## 2. 動作環境

| 項目 | 要件 |
|---|---|
| OS | Windows |
| Node.js | 推奨 v18 以上 |
| Python | 任意のバージョン（実行時のパスをアプリで指定） |
| ブラウザ | モダンブラウザ（Chrome / Edge など） |

## 3. 初回起動手順

### 3.1 リポジトリの取得と依存インストール

```bash
git clone <this-repo>
cd python-manager
npm install
```

### 3.2 開発サーバ起動

```bash
npm run dev
```

ブラウザで <http://localhost:3000> を開く。

### 3.3 セットアップウィザード

`appsettings.json` がリポジトリ直下にない初回は、全画面の **セットアップウィザード** が出る。以下 4 つを設定して保存する。

| 項目 | 例 |
|---|---|
| Python 実行ファイルパス | `C:/Python311/python.exe` |
| ツールルートフォルダ | `C:/PythonToolRunner/tools` |
| 既定の出力先 | `C:/PythonToolRunner/outputs` |
| ログ保存先 | `C:/PythonToolRunner/logs` |

保存すると `appsettings.json` が生成され、以降のアクセスではウィザードは出ず、左サイドバー＋メイン領域の通常レイアウトになる。

## 4. 画面・機能チェックリスト

> **注意**：このセクションは `/finalize-release` の乖離チェックが参照する **契約セクション**。
> 見出し名 `## 画面・機能チェックリスト` は変更せず、各画面エントリは `### /<route>` 形式で書くこと。
> 実装に新画面が追加されたら、ここにも対応する `### /<route>` 節を追加する必要がある（追加し忘れると finalize 時に `manual-drift.md` で指摘される）。

### /tools — ツール一覧

- アプリ起動後の最初に開く画面（`/` から自動リダイレクト）
- 規定フォルダ配下のすべての登録済みツールがテーブル表示される
- 上部の検索ボックスにツール名を入力すると、その場で絞り込まれる
- 行をクリックすると当該ツールの **パラメータ定義編集画面** へ遷移
- 行内の「実行」ボタンから直接 **Python 実行画面** へ遷移
- ツールがゼロ件のときは「右上の『新規作成』ボタンから始めてください」と案内

### /tools/[toolId]/edit — パラメータ定義編集

- 既存ツールのパラメータ定義（`tool.json` の `parameters` 配列）を編集する画面
- パラメータごとに以下を編集できる：パラメータ名 / 表示名 / 説明 / データ型 / UI 種別 / 入出力区分 / 必須有無 / 初期値（`default_value`） / 選択肢 / バリデーション / argparse フラグ名
- ここでは **`current_value` は編集不可**（実行時の値は `/run` 画面で設定する）
- 行追加・行削除・並び替えに対応
- 保存ボタン押下で `tool.json` の `parameters` と `default_value` のみを永続化
- 未保存中は同期ボタンが無効化される
- 同期ボタン押下で `tool.json` を正として `main.py` の argparse 定義を書き換え。書き換え前に `main.py.bak` を自動作成

### /tools/[toolId]/run — Python 実行

- 登録済みツールを実際に Python で走らせる画面
- 各パラメータに対応する入力 UI（テキスト／ファイル／フォルダ／数値／チェックボックス／セレクトなど）が並ぶ
- ここで設定する値は `current_value`。**パラメータの追加・削除・型変更・初期値変更はできない**（それは `/edit` 画面の責務）
- 「保存」ボタンで `current_value` のみを `tool.json` に永続化
- 「実行」ボタンで `python.exe main.py --xxx ...` が起動。標準出力・標準エラーは画面下部にライブで流れる
- `[PROGRESS] xx%` 形式の出力をスクリプトが吐けば、進捗バーがリアルタイム更新される
- 「停止」ボタンで実行中の Python プロセスを終了
- 実行完了後は **生成ファイル一覧** と **画像比較プレビュー** が表示される
- `.png` が出力されている場合のみ、入力画像と出力画像を左右 2 画面で比較。複数ペアはタブ切替

### /new — 新規ツール作成

- 雛形 `main.py` と `tool.json` を WebUI から生成する画面
- ツール名、説明、パラメータ初期セットを入力 → 「生成」で規定フォルダ配下に新フォルダ＋ファイル一式を作成
- 生成された `main.py` には argparse、`main()` 関数、入力読み込み・出力保存・ログ出力のテンプレートが含まれる
- 生成後は自動で `/tools` 一覧に戻り、新ツールが先頭付近に出る

### /import — 既存ツール登録

- 既に手元にある `.py` ファイルを WebUI から取り込む画面
- ファイルパスを指定 → 「解析」で `parser.add_argument(...)` の列挙を静的解析し、UI に検出結果を反映
- 解析できなかった範囲は手動で追記可能
- 登録ボタンで規定フォルダ配下に取り込まれ、`tool.json` が自動生成される

### /history — 実行履歴

- `history.json` から過去の実行履歴を読み出して一覧表示
- 各行に：スクリプト名、使用パラメータの要約、成功／失敗、実行時間、出力先、ログファイルパス
- 上部のフィルタで成功／失敗、ツール名で絞り込める
- 出力先パスをクリックすると OS のファイルエクスプローラで開く
- ログパスをクリックすると当該ログをアプリ内で表示

### /settings — アプリ設定

- セットアップウィザードで設定した 4 項目（Python 実行ファイルパス、ツールルート、出力先、ログ先）を後から変更する画面
- 値を書き換えて「保存」で `appsettings.json` に反映
- 反映後はページリロード不要で即時有効

## 5. よくある操作手順

### 5.1 新しいスクリプトを登録して実行する（雛形から）

1. 左サイドバー「新規作成」→ ツール名・説明・パラメータを入力
2. 「生成」で雛形が `main.py` と `tool.json` として作られる
3. 生成された `main.py` をエディタで開いて実処理を実装
4. ツール一覧から当該ツールを選び「パラメータ定義編集」で必要に応じて UI 種別・バリデーションを調整
5. 「Python 実行画面」で値を入れて「実行」

### 5.2 既存の自作スクリプトを取り込む

1. 左サイドバー「既存ツール登録」→ `.py` のパスを入力
2. 「解析」で argparse が読み取られる
3. 解析結果を確認し、不足分を「パラメータ定義編集」で補う
4. 「Python 実行画面」で値を設定して実行

### 5.3 実行履歴から過去の出力先を開く

1. 左サイドバー「実行履歴」
2. 該当行の出力先パスをクリック → OS のファイルエクスプローラが開く

## 6. データの保存場所

| 種類 | 場所 |
|---|---|
| アプリ共通設定 | リポジトリ直下 `appsettings.json` |
| ツール定義 | 規定ツールフォルダ配下の `<ToolName>/tool.json` |
| Python 本体 | 規定ツールフォルダ配下の `<ToolName>/main.py` |
| 同期前バックアップ | 同上の `<ToolName>/main.py.bak` |
| 出力ファイル | 既定出力先 + `<ToolName>_<yyyyMMdd_HHmmss>/` サブフォルダ |
| ログ | ログ保存先 + 実行ごとのログファイル |
| 実行履歴 | アプリ共通の `history.json` |

`tool.json` の編集は原則アプリ経由で行う。手で編集すると同期で上書きされる可能性がある。

## 7. トラブルシューティング

### Python 実行時に「python.exe が見つかりません」と出る

`/settings` 画面で **Python 実行ファイルパス** を見直す。`C:/Python311/python.exe` のように `.exe` まで含む絶対パスを指定する。

### 「パラメータ未保存」のまま同期ボタンが有効にならない

未保存の値変更があると同期は無効化される。先に「保存」を押してから「同期」を押す。

### 実行が止まらない

「停止」ボタンを押す。それでも残る場合は対象ポート（既定 3000）以外の Python プロセスを OS のタスクマネージャから終了。`taskkill /F /IM node.exe` のような全 node プロセス停止は **使わない**（dev サーバや MCP サーバを巻き添えにする）。

### ブラウザに何も表示されない

`npm run dev` のターミナル出力を確認。ポートが他プロセスに使われている場合、Next.js は自動で別ポート（3001 など）に切替えるため、その新ポートを開く。

### 同期で `main.py` が壊れた

`main.py.bak` から手動で復元する。同期は失敗時に `.py` を更新しない設計だが、念のため Git で履歴を管理しておくと安心。

## 8. 制限事項（初版スコープ外）

以下の機能は初版には含まれない（要件定義書 §4.2 参照）：

- 実行履歴からの再実行ボタン
- 複数スクリプトの直列／並列パイプライン UI
- ノードベースのフロー編集 UI
- `.raw` 形式のプレビュー
- 3 次元画像から 2 次元スライスを選定する専用 UI

将来拡張候補として要件定義書 §14 にロードマップが記載されている。
